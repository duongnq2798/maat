An agent that trades a tokenized stock meets failures that a token-only agent never does: a stock market that closes while the pool keeps trading, a price feed that goes quiet for the weekend, a split that rescales the token, an issuer that can pause it. This page is the checklist such an agent needs before every trade, one row per failure.

In Maat the agent does not run the checklist itself. Claude proposes, and the [vault](/docs/help/glossary#vault) runs every check inside `execute`, so the vault has the last word. A failed check does not [revert](/docs/help/glossary#revert): the vault records a [Decision](/docs/help/glossary#decision) with a typed reason, and moves no funds. Each row names that reason and links the line of the contract that returns it.

## The checklist

A `BUY` meets the first twelve rows in this order; then come a payment, the credit actions, and the two ways the action itself can fail. There are <Fact name="refusalCount" /> rows, one per refusal code. Where a code is returned from more than one line, the row links the first; <a href="/reasons.json">/reasons.json</a> lists them all, and [reasons-json.test.ts](https://github.com/duongnq2798/maat/blob/main/web/test/reasons-json.test.ts) reads the contracts to keep every line in step.

## Four patterns and what they cannot show

Where the checks live decides what an agent can prove. Each pattern below can run some of the checklist, but leaves one thing unshown.

| Pattern | What it cannot show | Maat | Source |
| --- | --- | --- | --- |
| A guard that reverts | Its refusals leave no event: a revert undoes the logs | A Decision event with a typed reason, from an `execute` that returns normally | [`MandateVault.sol:112`](https://github.com/duongnq2798/maat/blob/main/contracts/src/MandateVault.sol#L112) |
| A testnet mirror | No real gap, slippage or premium | The real B20 stock tokens, their Aerodrome pools and Chainlink's equity feeds on Base, as the deploy wires them in | [`BaseAddresses.sol:13`](https://github.com/duongnq2798/maat/blob/main/contracts/script/BaseAddresses.sol#L13) |
| An offchain rule engine | Nothing onchain bounds the agent | The vault runs every check itself, inside `execute`, on each intent the [executor](/docs/help/glossary#executor) sends | [`MandateVault.sol:109`](https://github.com/duongnq2798/maat/blob/main/contracts/src/MandateVault.sol#L109) |
| An agent that prices its own oracle | Its own bad price is approved | The vault reads Chainlink and the pool itself; an intent's `minOut` can only raise the vault's own slippage floor | [`GuardLib.sol:50`](https://github.com/duongnq2798/maat/blob/main/contracts/src/GuardLib.sol#L50) |

## Ask the vault before you trade

Any agent can ask the same contracts the same questions, read-only. `previewIntent` returns the reason `execute` would reach for an intent now, before it acts. It cannot predict a failure of the action itself: `SWAP_FAILED`, `TRANSFER_FAILED`, or a `CREDIT_FAILED`, `HEALTH_FACTOR_LOW` or `DERISK_WINDOW` from the credit call. The market-guard skill (<a href="/skill.md">/skill.md</a>) wraps it and the calendar in a Node script with no dependencies. <a href="/reasons.json">/reasons.json</a> lists every reason with its id, meaning, group, the check above and each line that returns it, so a tool can decode a `Decision` without reading the contracts.
