## About Maat

### What is Maat?

Maat is an onchain [vault](/docs/help/glossary#vault) on [Base](/docs/help/glossary#base) and the [mandate](/docs/help/glossary#mandate) it keeps. Its AI agent, Maat's agent, is built to trade [tokenized stocks](/docs/help/glossary#tokenized-stock) from the vault's own treasury. Claude proposes. The vault decides. It checks each [intent](/docs/help/glossary#intent) the [executor](/docs/help/glossary#executor) sends against the mandate and records the verdict. It is built and fork-tested, and its five contracts, the four core Maat contracts and `MaatInbox`, are deployed on Base mainnet. See [What is Maat](/docs/get-started/what-is-maat).

### Is Maat live?

Partly. The four core Maat contracts and `MaatInbox` are deployed on Base mainnet, and they are unaudited. The contracts and the agent's send path have run on a local fork of Base mainnet, which is why most pages of the docs carry the Fork-tested label; the pages about the deployed contracts carry Live on mainnet. There a scripted proposer stood in for Claude and a local sender for the CDP wallet. Since 2026-11-27 the agent runs in live mode on Base mainnet, on the owner's PC, with the real Claude API, and the CDP Server Wallet is the vault's executor. The vault's first two mainnet `Decision` events were the owner's smoke-test buys of 2026-11-24. The agent's first came at 02:14 UTC on 2026-11-27: Claude proposed a buy of 4.68 USDC of GOOGLc while NYSE was closed for Thanksgiving, and the vault refused it with `MARKET_CLOSED` ([transaction](https://basescan.org/tx/0xca9e2dfe58cea6dc033292a1733a64658e702c3de25627ee7af136d42a38bed6)). See [Status and roadmap](/docs/get-started/status).

### Whose money does Maat trade?

Only its own. Agent #1 is one agent with one vault, owned by the team, and it is built to trade only its own treasury, which the design spec sizes at <Fact name="treasuryUsd" />. See [What exists today](/docs/get-started/what-is-maat#what-exists-today).

### Can I invest in Maat or deposit into a vault?

**No. Only the [owner](/docs/help/glossary#owner) can fund a vault or withdraw from it.**

- Only the owner can call `fund`, and `withdraw` pays only the owner.
- USDC sent to a vault by a plain transfer is not a deposit. The next time `notifyRevenue` runs, the vault counts it as revenue. Its `RevenueReceived` event carries only the amount, and the USDC joins the treasury: the sender gets no claim on the vault and cannot get the USDC back, and only the owner can withdraw it.

See [What it is not](/docs/get-started/what-is-maat#what-it-is-not), and [`notifyRevenue`](/docs/reference/mandate-vault#notifyrevenue) and [`fund`](/docs/reference/mandate-vault#fund) for the functions.

### Is there a Maat token?

No. The repository has no Maat token. No contract in `contracts/src` or `contracts/script` is a token: `contracts/src` holds the vault, the market calendar, the swap and credit adapters, the briefs inbox `MaatInbox`, the libraries they use, shared types and events, and interfaces. Outside the third-party libraries in `contracts/lib`, the only token contracts are the test mocks in `contracts/test/mocks` (`MockERC20`, `MockB20` and `MockFaultyERC20`), which the contract unit tests deploy as stand-ins for USDC and the stocks. So a token offered under Maat's name today does not come from this code.

### How will I know the real vault address?

**From the table in `deployments/README.md`, which the Status page shows under [Next: mainnet](/docs/get-started/status#next-mainnet).**

- That table lists the four Maat contracts and `MaatInbox` with their addresses and deploy transactions ([`deployments/README.md`](https://github.com/duongnq2798/maat/blob/main/deployments/README.md)). [Base addresses](/docs/reference/base-addresses) shows it too, and each address there links to Basescan.
- The pages about the deployed contracts, Base addresses among them, carry the Live on mainnet label ([What the three labels mean](/docs/get-started/status#what-the-three-labels-mean)).
- Treat a vault address from any other source as unverified.

### Can Claude move funds on its own?

**No. Claude only proposes, and the vault checks every intent.**

- Claude cannot choose the verdict, set the [slippage](/docs/help/glossary#slippage-floor) or pay a bill.
- `execute` is the executor's only way to move anything, and the vault runs its own checks on every intent. A confused Claude, a bug in the agent or a stolen executor key meets the same rules.
- No human signs off each trade. In [live mode](/docs/help/glossary#live-mode), the agent is built to send any proposal that passes its own validation and a [preview](/docs/help/glossary#preview) of `OK`, up to `MAAT_MAX_TX_PER_DAY` transactions a UTC day (<Fact name="maxTxPerDay" /> by default), so no person stands between Claude's proposal and the vault's checks.

See [What none of the agent's steps can do](/docs/get-started/how-a-decision-is-made#what-none-of-the-agents-steps-can-do).

### Is Maat a hackathon project?

Yes. Maat is an entry in Base's Stocks Maxxing Season Builder Quest (5 November to 12 December 2026), track Agentic Stock Finance. All the code in the repository was written during the Quest, starting with commit `009577d` on 2026-11-06. Each part began as a design spec and a written plan and was then built with Claude Code. The specs and plans are in [`docs/superpowers`](https://github.com/duongnq2798/maat/tree/main/docs/superpowers). See [Project start](/docs/help/changelog#project-start).

## Watching the agent

### What happens on a Saturday?

**A `BUY` or a `SELL` is refused with `MARKET_CLOSED`, and no money moves.** The calendar contract reports the market closed all Saturday in both [session modes](/docs/help/glossary#session-mode).

- A check that comes earlier and fails is reported instead. The vault pause comes first and stops every [action](/docs/help/glossary#action) except `REPAY`, so a paused vault answers `VAULT_PAUSED` to a `BUY` or a `SELL`.
- `SUPPLY`, `REPAY` and `PAY_EXPENSE` do not need an open market. Their own checks still apply.
- `WITHDRAW_COLLATERAL` needs no open market when there is no debt, and its own checks still apply. While there is debt it is refused with `MARKET_CLOSED`.
- `BORROW` is refused with `MARKET_CLOSED`.
- A [refusal](/docs/help/glossary#refusal) is recorded as a [`Decision`](/docs/help/glossary#decision) only when the agent sends the intent. The agent is built to send a refusal onchain at most once per [reason](/docs/help/glossary#reason) per NYSE date, and a `MARKET_CLOSED` once per closed phase of that date.

In the fork run, with the clock moved ahead to a Saturday, the agent's buy of GOOGLc was refused this way, and the transaction that recorded it used <Fact name="gas.refusalLog" /> gas. See [Worked example: the Saturday buy](/docs/get-started/how-a-decision-is-made#worked-example-the-saturday-buy).

### Why refuse instead of revert?

A [reverted](/docs/help/glossary#revert) call leaves no record, while a refusal emits a typed `Decision` event with the reason, so every refused call can be read later. By design `execute` reverts only for a call from the wrong address (`NotExecutor`) or a reused intent id (`IntentAlreadyUsed`). [Some failures escape](/docs/security/model#fail-closed): a dependency can still make `execute` revert in a few ways the vault does not catch, such as return data that does not fit the ABI. A refused intent still spends its id, so it cannot be replayed. See [Step 4: the vault decides](/docs/get-started/how-a-decision-is-made#step-4-the-vault-decides).

### How often does the agent run?

The agent is built to run one [round](/docs/help/glossary#round) every <Fact name="loopMinutes" /> while the market is open under the mandate's session mode, and every <Fact name="offSessionMinutes" /> otherwise. The wait after a round depends only on whether that round read an open market:

- A round that could not read the vault or the calendar, or that threw an error, waits <Fact name="offSessionMinutes" />.
- A round that [halted](/docs/guides/run-the-agent#recover-from-a-halted-round) after reading an open market runs again <Fact name="loopMinutes" /> later.

The agent has run in live mode on Base mainnet only since 2026-11-27, so this is the cadence the code is built to keep; these docs record no measurement of it yet. See [Cadence](/docs/concepts/treasury-loop#cadence).

### Why is there no Decision for every proposal?

The agent previews every intent first, and it sends a refusal onchain only when the refusal is worth recording and its reason has not been logged on the current NYSE date (for `MARKET_CLOSED`, in the current closed phase of that date). Other refusals, such as `INSUFFICIENT_BALANCE`, go to the agent's [journal](/docs/help/glossary#journal) only. So a missing `Decision` is not proof that the agent did not try. See [What a decision does not tell you](/docs/get-started/read-a-decision#what-a-decision-does-not-tell-you).

### What if the calendar misses a holiday?

The calendar ships with <Fact name="calendarPreload.holidays" /> holidays and <Fact name="calendarPreload.earlyCloses" /> early closes up to 2027-12-24, and later holidays need `addHoliday` from the calendar owner. If one is missing, the calendar treats that day as a normal session, so the market check passes. The other checks still run, but the vault can still trade on the last published price until it is older than `maxStaleness`, which with the default of <Fact name="mandate.maxStalenessSec" /> may not happen during the holiday. The premium check still refuses a buy or a sell once the pool drifts too far from that price. See [What happens if a holiday is missing](/docs/concepts/market-hours#what-happens-if-a-holiday-is-missing).

## For developers

### How do I check Maat's claims myself?

Clone the repository and run the tests. The refusal test, the contract suites, the agent tests and the site build need no wallet, RPC URL or API key and touch no chain, though you need network access to clone the repository and install packages, and the whole path takes about five minutes on a fresh clone. The [fork tests](/docs/help/glossary#fork-test) are optional and need a Base archive RPC. See the [Quickstart](/docs/get-started/quickstart). [How it is tested](/docs/security/testing) names the test behind each guarantee in the security model.

### How is Maat tested?

**Unit and invariant tests against mocks, fork tests against real Base state, and parity tests that hold the site to the code. No test touches the real Claude API or the CDP wallet.**

- **Contracts.** Unit tests run the vault, the guards, the calendar, the price math, both adapters and the deploy script's payee list against mocks, an invariant suite checks the vault's rules over random sequences of calls on the same mocks, and Foundry fork tests run the contracts against real Base state at two pinned mainnet blocks.
- **Agent.** Its tests use fakes, and its fork run uses a scripted proposer and a local sender.
- **Website.** Its tests read the Solidity sources and the fork-run gas log, so most numbers on a page fail them if they drift from the code.

See [How it is tested](/docs/security/testing), which maps each guarantee in the security model to the test that shows it and lists what is not tested. The [Quickstart](/docs/get-started/quickstart#the-five-steps) runs the suites that need no RPC URL, and the fork tests are an optional step there.

### Has Claude or the CDP wallet run for real?

Since 2026-11-27, yes, in live mode on Base mainnet: the agent calls the real Claude API, and the vault's executor is its [CDP wallet](/docs/help/glossary#cdp-server-wallet) account. The agent's first `Decision` went through that wallet at 02:14 UTC that day ([transaction](https://basescan.org/tx/0xca9e2dfe58cea6dc033292a1733a64658e702c3de25627ee7af136d42a38bed6)). In the fork run a scripted proposer stood in for Claude and a local sender for the CDP wallet. In the tests, the Claude proposer and the CDP code run against fakes. See [Built and fork-tested](/docs/get-started/status#built-and-fork-tested).

### Which functions can anyone call on a vault?

**Anyone can call `notifyRevenue`, `syncMultiplier`, `previewIntent` and the view functions.**

- `execute` is for the executor.
- The owner functions are for the owner: `setPaused`, `setExecutor`, `withdraw`, `fund`, the three `queue` functions, `cancelChange` and the three `apply` functions.
- One catch: the [transfer-policy check](/docs/concepts/nine-checks#3-transfer-policy) reads `tx.origin`, the account that signed the outer transaction, not the executor address that `execute` checks. For an executor that is a plain account with no code, such as the agent's CDP account, the two are the same, so call `previewIntent` from the executor's address to get the answer `execute` would. If the executor has code, for example a multisig, preview from the account that will submit the transaction.

See [Three roles](/docs/concepts/timelock-and-roles#three-roles).

### Is there an API or SDK?

**No. Maat has no API or SDK to integrate with today.**

- What exists is the code in the repository: the Solidity contracts, the TypeScript agent and their tests, which you can read, run and deploy yourself.
- The only client software for a vault is the agent's own code.
- To send intents (`execute`) from your own code, deploy your own vault and hold its executor key. Reading a vault and calling `previewIntent` need no key. [Send intents from your own code](/docs/guides/deploy-your-own-vault#send-intents-from-your-own-code) lists the steps, with the agent's own code where it helps.
- Anything not built yet is listed on [Status and roadmap](/docs/get-started/status).

See [What it is not](/docs/get-started/what-is-maat#what-it-is-not).

## For builders

### Can I run my own vault?

**Yes, with a caveat: the contracts are MIT-licensed but unaudited.**

- The deploy script reads the deployer, owner and executor addresses and one or two expense [payee](/docs/help/glossary#payee) addresses from environment variables. It builds the vault from `MaatConfig` and Maat's Base mainnet addresses, with the default mandate and the three-stock basket, so for another mandate you edit `MaatConfig.sol` first.
- You sign every transaction from your own wallet.
- The owner address cannot be changed afterwards, so check it character for character before you broadcast.

See the checklist in [Next: mainnet](/docs/get-started/status#next-mainnet), and [Deploy your own vault](/docs/guides/deploy-your-own-vault) for the commands.

### Can I try it on a testnet?

**No. The agent and the deploy are built for Base mainnet only.**

- The agent's chain client uses viem's `base` chain. Its CDP sender sends only on the `base` network, and its CDP policy accepts sends only there.
- The deploy script uses Base mainnet addresses for USDC, the stock tokens, their [feeds](/docs/help/glossary#chainlink-equity-feed) and [pools](/docs/help/glossary#aerodrome-slipstream), and [Aave V4](/docs/help/glossary#aave-v4), and the agent's address book lists the Base mainnet USDC and stock tokens ([Base addresses](/docs/reference/base-addresses)).
- To try it without money, use a local fork of Base mainnet: the contract [fork tests](/docs/get-started/quickstart#optional-the-fork-tests), the [deploy dry run](/docs/guides/deploy-your-own-vault#dry-run-it-on-a-fork) and the [agent's fork run](/docs/guides/reproduce-the-fork-run). Each needs a Base mainnet RPC URL, and none sends a transaction to Base.

### What can I set in a mandate?

**Three things: the mandate's own fields, each stock's settings and the payee allowlist.**

- **The mandate** holds the session mode, the [premium](/docs/help/glossary#premium), slippage and [staleness](/docs/help/glossary#staleness) limits, the [multiplier](/docs/help/glossary#uimultiplier) cooldown, the [TWAP](/docs/help/glossary#twap) window, the per-trade and daily caps, the calendar and adapter addresses, the [health factor](/docs/help/glossary#health-factor) limits and the [de-risk window](/docs/help/glossary#de-risk-window) ([Field by field](/docs/concepts/mandate#field-by-field)).
- **Each stock's settings** say whether it is allowed, and give its feed, its pool and its largest share of net equity.
- **The payee allowlist** holds the addresses that `PAY_EXPENSE` can pay.

The agent's code knows only NVDAc, GOOGLc and AAPLc, so for the agent to trade another stock its code must change too ([Change it](/docs/guides/configure-a-mandate#change-it)).

### How do I change a rule after deploying?

The owner queues the change, waits <Fact name="timelockHours" />, and then applies exactly the queued values within <Fact name="gracePeriodDays" />, or cancels it. Even a tighter limit waits, while pausing the vault and rotating the executor key do not. See [The timelock](/docs/concepts/timelock-and-roles#the-timelock).

### What does the agent cost to run?

**Claude API fees in every mode, plus gas in [live mode](/docs/help/glossary#live-mode). The vault does not pay Anthropic.**

- A [dry run](/docs/help/glossary#dry-run) still calls Claude, so it costs real API fees even though it sends nothing. The README estimates roughly one cent of Claude usage per round. That is an estimate: the Claude proposer is tested against a fake client, and these docs record no measured cost from the live agent's Claude calls, which began on 2026-11-27.
- In live mode the executor also needs ETH on Base for gas, <Fact name="executorGasEth" /> by the agent README's estimate.
- The agent is built to track its own [compute bill](/docs/help/glossary#compute-bill) and pay it from the vault in USDC with `PAY_EXPENSE`. The vault pays an allowlisted [payee](/docs/help/glossary#payee), the wallet that pays for the Claude usage (for Agent #1, the owner's). Each payment counts toward the same per-trade and daily caps as trades.

See [Paying its own bill](/docs/concepts/treasury-loop#paying-its-own-bill).

### What happens if Claude is unavailable?

**The round goes on without Claude's proposals, and the next round asks Claude again.**

- The request turns on the API's server-side fallback (`fallbacks: "default"`), so when the requested model declines, the answer may come from another model ([`MAAT_LOOP_MODEL`](/docs/reference/agent-configuration#maat_loop_model)). The round loses Claude's proposals only in the cases below.
- A call that fails before Claude answers comes back as the error `claude: <message>` with a cost of zero. An answer that arrives but cannot be used, such as a refusal, a cut-off answer or invalid JSON, is billed at its token cost. A malformed response, one with no usage or content, comes back as `claude: malformed response: <message>`, also with a cost of zero.
- The round writes `ok: false` and the error on its `run` line in the journal.
- A compute bill that is due is still queued as a `PAY_EXPENSE`, then previewed and gated like any other intent.
- The next round follows the normal [cadence](/docs/concepts/treasury-loop#cadence).

This is tested against fakes only: the proposer test `never throws on an API error` covers a failed call, and the `runOnce` test `bills a failed Claude call and still settles bills` covers the `run` line with `ok: false` and the error. See [Step 2: the policy and Claude](/docs/get-started/how-a-decision-is-made#step-2-the-policy-and-claude).

## Trust and safety

### What if the executor key is stolen?

**The attacker can only call `execute`, so every intent still goes through the vault's checks. The caps bound trades and bill payments, not credit actions.**

- Trades and bill payments are held to the per-trade cap of <Fact name="mandate.perTradeCapUsd" /> and the daily cap of <Fact name="mandate.dailyCapUsd" /> in the default mandate, every UTC day until the key is replaced. Inside those caps the attacker can make bad trades within the mandate and pay an allowlisted payee, but cannot pay any other address or change the mandate.
- Credit actions are not capped. The attacker can supply the allowed stocks to Aave and borrow USDC against them down to the health factor floor of <Fact name="mandate.minHealthFactor" /> (<Fact name="mandate.targetHealthFactor" /> inside the [de-risk window](/docs/help/glossary#de-risk-window)), and leave the debt open. The borrowed USDC goes to the vault.
- The owner can replace the key at once with `setExecutor`.

The fork test `test_compromisedExecutorIsBounded` shows the payee and per-trade limits against real Base state. It deploys the vault without a credit adapter, so it does not try a borrow. See [If a key leaks](/docs/concepts/timelock-and-roles#if-a-key-leaks), and [the threat model](/docs/security/threat-model#the-executor-key), which goes through every key that could leak.

### What if the owner key is stolen?

The owner key is a different case from the executor key. It is fixed for the life of the vault, and `withdraw`, `setPaused` and `setExecutor` do not wait for the timelock, so a leaked owner key can take what the vault holds at once. The README lists the single-key owner as a known limitation: a multisig owner would work with the contract but is not set up. See [If a key leaks](/docs/concepts/timelock-and-roles#if-a-key-leaks), and [the threat model](/docs/security/threat-model#the-owner-key) for this case and the other keys.

### Can the agent still make a bad trade?

Yes. The vault does not judge whether a trade is a good idea, so a trade inside every limit is allowed, even a bad one. The limits, such as the per-trade cap of <Fact name="mandate.perTradeCapUsd" /> and the daily cap of <Fact name="mandate.dailyCapUsd" /> in the default mandate, bound how much a bad trade can cost. See [What the checks do not do](/docs/concepts/nine-checks#what-the-checks-do-not-do).

### Does it give investment advice?

No. Maat gives no investment advice, confers no shareholder rights and is not offered to US persons. It is built to hold only its own treasury, and an allowed verdict only means a trade stayed inside the mandate, not that it is a good idea. See [What it is not](/docs/get-started/what-is-maat#what-it-is-not).

### Has it been audited?

No. There is no third-party audit, so treat the contracts as unaudited, including the five Maat contracts deployed on Base mainnet. The README lists this first among its known limitations. See [What Maat does not claim](/docs/security/not-claimed#unaudited) for the limitations, and [Status and roadmap](/docs/get-started/status#built-and-fork-tested) for what is built.

### How do I know the numbers on the site are real?

Most figures are rendered from a facts file with its source, and the tests check most of those against the code or the spec. A few cite documents instead: the planned [x402](/docs/help/glossary#x402) price and the treasury size cite the treasury design spec, and the AMZNc pool liquidity cites the README and that spec. The check count cites that spec too, and its only test compares it with the site's own list of check labels, not with the contract. Every code excerpt in these docs is compared with the file it quotes. See [How this page stays honest](/docs/get-started/status#how-this-page-stays-honest).
