By the end of this page you will have watched the vault refuse a Saturday buy without reverting, and run the contract, agent and website tests on your own machine. It is written for developers and evaluators, and it lets you check Maat's claims against its code yourself. You need no wallet, no RPC URL and no API key: every test runs against mocks and fakes, so nothing touches a chain. You do need network access to clone the repository and install packages. The first compile in step 2 also downloads solc <Fact name="solidityVersion" />, the compiler version `contracts/foundry.toml` pins, if Foundry does not have it yet.

Not a developer? [What is Maat](/docs/get-started/what-is-maat) explains the idea without code, and [Status and roadmap](/docs/get-started/status) says what is real today.

## Prerequisites

Time: about 4 minutes on a fresh clone. The five steps were timed by hand on 2026-11-07 at commit `4492eed`, on Windows 10. Most of it went to compiling the contracts and to the two `npm ci` runs. That was before the docs center, and the steps have not been re-timed.

| Tool | Version | Why |
| --- | --- | --- |
| git | Not pinned | Clones the repository and its two direct submodules. |
| [Foundry](https://getfoundry.sh) | 1.8.4 or newer | `contracts/foundry.toml` sets `hardfork = "base:Cobalt"`, which the B20 stock precompiles need. |
| Node.js with npm | 24 | Runs the agent tests and the website. |
| bash | Linux, macOS, or Git Bash on Windows | Runs the commands exactly as written below. |

## The five steps

<Steps>

<Step>

### Clone and initialize the submodules

Only the two direct submodules are needed (forge-std and v4-core). Do not pass `--recursive`.

```bash
git clone https://github.com/duongnq2798/maat.git
cd maat
git submodule update --init
```

</Step>

<Step>

### Watch the vault refuse a Saturday buy

This unit test sets the clock to Saturday 2026-10-31 at 18:00 UTC and asks the vault to buy a mock [B20](/docs/help/glossary#b20) stock with USDC. The first run compiles the contracts.

```bash
cd contracts
forge test --match-test test_refusalIsLoggedNotReverted -vvvv
```

Read the trace from the top. After taking a snapshot of the token's multiplier, the vault checks that the token is in the [mandate](/docs/help/glossary#mandate) (check 1, a storage read that the trace does not show), reads its pause flag (check 2) and its four transfer-policy legs (check 3), then asks the calendar, which says the market is closed (check 4). `reason: 6` is `MARKET_CLOSED` in [Types.sol](https://github.com/duongnq2798/maat/blob/main/contracts/src/Types.sol). `execute` returned normally, so it did not revert. The vault's USDC balance read near the end still returns `200000000`, the amount it started with, and `usedIntent` returns `true`: the [intent](/docs/help/glossary#intent) id is spent, so the same request cannot be replayed.

Your full trace shows two things that the ellipses hide here. First, an `emit Decision` line right after `VM::expectEmit` and before `execute` is called. That is the test declaring the [Decision](/docs/help/glossary#decision) event it expects, not the vault: the vault's own emit is the one inside `execute`. Second, four `policyId` reads where this trace shows one, one per leg of a buy: the pool as sender, the vault as receiver, the pool as the transfer's executor (the B20 term for the account that moves the tokens), and `tx.origin`, the account that sent the transaction, under the same executor policy.

### Run the website's tests and build it

The website tests read the Solidity sources and the committed fork-run gas log, so most numbers on a page fail here if they drift from the code. The same tests check these docs: a page fails if its text outside the frontmatter, code and the attributes of component tags types out by hand a fact, one of the named values the docs render with `<Fact>`, that contains three or more digits in a row (dates aside), a dollar amount or a [bps](/docs/help/glossary#basis-point-bps) value; most facts are checked against the contracts, the agent or the fork-run gas log; and every code excerpt is compared with the lines it quotes.

```bash
cd ../web
npm ci
npm test

npm run check:out
```

## Check it worked

- Every Foundry suite reports `0 failed`. Vitest prints only `passed` counts when all tests pass, and a `failed` count appears next to them when one does not.
- The refusal trace from step 2 shows `allowed: false, reason: 6`.
- The website check prints a line that starts with `out/ is ready to deploy`, then the size of the search index.

To check one claim at a time, [How it is tested](/docs/security/testing) names the test behind each guarantee and shows how to run it alone. For a contract test, that is the same `--match-test` filter as step 2.

If something else shows up, [Troubleshooting](/docs/help/troubleshooting) lists symptoms, causes and fixes.

To find your way around the code, the [Repository map](/docs/reference/repository-map) says what each main folder holds and which docs page to read before you open it.

## Optional: the fork tests

The contract [fork tests](/docs/help/glossary#fork-test) run the real B20 tokens, feeds, pools and [Aave V4](/docs/help/glossary#aave-v4) at two pinned mainnet blocks. They need a Base archive RPC, which you pass as `<BASE_RPC_URL>`. No archive RPC of your own? `contracts/.env.example` lists a public Base endpoint that served archive state when it was tested on 2026-11-06. Export that URL as `BASE_RPC_URL`, and if it answers with HTTP 429, use a free key from an RPC provider instead. Nothing is broadcast: Foundry forks the chain locally. Run these commands from the repository root. Step 5 ended in `web/`, so go back with `cd ..` first.

```bash
cd contracts
export BASE_RPC_URL=<BASE_RPC_URL>   # your Base mainnet archive RPC URL
forge test --match-path "test/fork/*"
```

Expected output, from README.md, How to evaluate Maat in 5 minutes, with the counts replaced:

```text
Ran … test suites in …: … tests passed, 0 failed, 0 skipped (… total tests)
```

To run only the fork test that plays a compromised [executor](/docs/help/glossary#executor) against real Base state, use the same filter as step 2, in the same shell:

```bash title="contracts/"
forge test --match-test test_compromisedExecutorIsBounded
```

It has the executor try to pay an address that is not a [payee](/docs/help/glossary#payee), buy above the per-trade cap and call `withdraw`. The vault refuses the first two, the third reverts, and the vault keeps its USDC.

[Run the tests](/docs/guides/run-the-tests) covers every suite, including the agent's fork tests, and what each one needs.

## Common mistakes

- **Foundry is too old.** The `hardfork = "base:Cobalt"` setting needs Foundry 1.8.4 or newer. Run `forge --version` and update Foundry if it is older.
- **`--recursive` on Windows.** The nested submodules of v4-core hit the Windows path-length limit, and Maat does not need them. Clone into a short path and run `git submodule update --init` without `--recursive`.
- **CRLF line endings.** The repository's `.gitattributes` checks text files out with LF on every OS, so tests that parse source files behave the same on Windows. If your files have CRLF line endings anyway, see [Troubleshooting](/docs/help/troubleshooting) for the symptom and the fix.
