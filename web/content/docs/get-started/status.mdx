## Next: mainnet

The owner deploys by hand. Every mainnet transaction is signed from the owner's own wallet, and no script in the repository holds a key. The checklist, in order:

1. **Deploy.** Simulate with the real configuration and check the printed owner address character for character, because the owner is immutable. Then broadcast. The commands are in [Deploy your own vault](/docs/guides/deploy-your-own-vault).
2. **Fund.** Approve the USDC, then call `fund(amount)` on the vault. Do not transfer USDC straight into it, because `notifyRevenue` would record that as revenue.
3. **Hand the executor role to the CDP wallet.** Until then the executor is the owner's own wallet. The agent's `cdp-setup.ts` script prints the CDP executor address, and the owner then calls `setExecutor`.
4. **Record the first real `Decision`.** A smoke test sends one small buy during US market hours, which must be allowed, and one buy on a weekend, which must be refused with `MARKET_CLOSED`. The addresses and transaction hashes then go into the table in `deployments/README.md`.

Until the owner deploys, no page in these docs is labeled live, and the site's ledger shows only the fork run.

## Planned, not built

<Callout type="note" title="Planned">

None of this is built. W2 and W3 are the next two stages of the website, as the web design spec lays them out.

1. **A live ledger, a dashboard and a Base App mini-app manifest (W2).** The ledger would read `Decision` events from the mainnet vault. It needs the mainnet deploy first.
2. **An x402 Guard Service.** Other agents would pay <Fact name="x402Price" /> per "is this trade safe now?" check, and that USDC would fund the treasury loop. It is not implemented anywhere in the repository.
3. **A Guard Service HTTP API, an MCP server and a Bankr Skill** that expose the same check.
4. **`MandateFactory`.** Any agent would deploy its own vault with its own mandate. It is a stretch goal.
5. **A daily diary and a replay page for the fork scenarios (W3).**

</Callout>

## How this page stays honest

- Every page sets its label in its frontmatter, and a test rejects any value other than the three above.
- Nothing is labeled live until the owner deploys. The address table in `deployments/README.md` is empty today.
- Numbers come from facts that tests check against the contracts, the agent and the fork-run gas log. The planned x402 price cites the design spec, because nothing in the code can prove it.
- Test counts are not shown, because they go stale. The [Quickstart](/docs/get-started/quickstart) shows how to run the suites yourself.
- The date at the top of each page, Last reviewed, says when the page was last checked against its sources.
