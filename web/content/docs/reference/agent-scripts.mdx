This page covers the npm scripts in `agent/package.json` and the files in `agent/scripts`. It says what each one runs, which flags and modes it takes, what it needs, and which ones call a service outside your machine, so you know what is safe to run before you run it. Run every command from the `agent/` directory. `agent/package.json` sets Node 22.9 or newer in `engines` for the whole package, so every entry needs it. Run `npm ci` in `agent/` once before the first one. The agent is built and fork-tested, and it has run in [live mode](/docs/help/glossary#live-mode) only on a fork, with a scripted proposer in place of Claude and a local sender in place of the [CDP wallet](/docs/help/glossary#cdp-server-wallet). [Messages the agent prints](#messages-the-agent-prints-from-the-code-and-unit-tests-none-seen-in-a-live-run) quotes what the agent prints when it stops or a [round](/docs/help/glossary#round) goes wrong.

| Entry | What it does | What it needs | Outside services |
| --- | --- | --- | --- |
| `npm run agent` | Runs one round or the loop | The settings in [Agent configuration](/docs/reference/agent-configuration) | Your [Base](/docs/help/glossary#base) RPC, Claude (paid) in every mode, and the CDP Server Wallet in live mode |
| `npm test` | Runs the unit tests | Nothing | None |
| `npm run test:integration` | Runs the [fork test](/docs/help/glossary#fork-test) | A Base archive RPC and the Base build of Anvil | Your Base RPC. No Claude call and no CDP call |
| `npm run typecheck` | Type-checks the TypeScript | Nothing | None |
| `npm run gen:abi` | Rewrites the generated ABI file | The compiled contracts | None |
| `cdp-setup.ts` | [Owner](/docs/help/glossary#owner) only. Creates the [executor](/docs/help/glossary#executor) account and its policy | The three CDP credentials | Coinbase CDP |
| `first-decision.ts` | For the owner. Builds one `BUY` [intent](/docs/help/glossary#intent) offline and prints its calldata and `cast` commands | A vault address and a Builder Code | None |
| `gen-abis.ts` | The file that `npm run gen:abi` runs | See `gen:abi` | None |
| `smoke-claude.ts` | Asks Claude for one proposal | `ANTHROPIC_API_KEY` | Claude (paid) |

## npm scripts

### agent

<ScriptEntry name="agent" />

Starts the agent. Node loads `.env` from the current directory if the file exists, and `tsx` runs the TypeScript source, so there is no build step. To pass a flag through npm, put `--` before it. `main.ts` reads only the flags below and ignores every other argument, so a misspelled flag does not stop the start. A misspelled `--once` starts the loop:

| Flag | Effect |
| --- | --- |
| `--once` | Run one round and exit. Without it, the agent keeps running |
| `--dry-run` | Force [dry-run](/docs/help/glossary#dry-run) mode, whatever `MAAT_MODE` says |

The mode comes from `MAAT_MODE`, which is `dry-run` by default, and `--dry-run` overrides it. The flag is applied after the settings are checked, so `MAAT_MODE=live` without `MAAT_BUILDER_CODE` still stops the start. This is the command from `agent/README.md` for a single dry-run round:

```bash
cd agent
npm run agent -- --once --dry-run
```

It needs a [vault](/docs/help/glossary#vault) to read and makes a paid call to Claude, so this page shows the command and no output.

At startup the agent takes a lock on its data directory, before it opens its files or connects to CDP, so a second agent on the same directory stops. How it ends depends on the flags:

- With `--once` it prints one line with the mode, the vault, the executor and the data directory, runs one round, prints the round's report as JSON, releases the lock and exits. The report includes the run id, the `status`, the block it read, `marketOpen`, the hashes in `sent`, the counts `skipped` and `proposals`, and a `haltReason` when the round halted.
- Without `--once` it runs a round, then waits. The wait is <Fact name="loopMinutes" /> after a round that saw the market open, and <Fact name="offSessionMinutes" /> after any other round, including a round that threw an error. The agent logs a round that throws and tries again after the longer wait.
- A stop signal (Ctrl+C, or SIGTERM) ends the wait. It does not interrupt a round in progress: the agent finishes that round, releases the lock and exits.

The exit code does not tell you how a round went. `main.ts` sets no exit code, so a round that halts exits like a round that completes, and the `status` in the report is the thing to read. The process ends with an error when something throws outside the round's own handling, for example an invalid configuration, a lock held by another agent, a failed CDP lookup in live mode, or an unexpected error in a `--once` round. [Messages the agent prints](#messages-the-agent-prints-from-the-code-and-unit-tests-none-seen-in-a-live-run) quotes the agent's own errors that stop a start. When a round halts or leaves a transaction pending, [agent/README.md](https://github.com/duongnq2798/maat/blob/main/agent/README.md#after-a-halted-or-pending-tx-cycle) says what to read and what the next round does.

### test

<ScriptEntry name="test" />

Runs the unit tests in `agent/test`, and skips `agent/test/integration`. The tests replace Claude, the CDP wallet and the chain with fakes, so they need no API key, no RPC URL and no wallet, and they send nothing.

```text
      Tests  … passed (…)
```

### test:integration

<ScriptEntry name="test:integration" />

Runs the fork test in `agent/test/integration`, one file at a time and with long timeouts. The test forks Base mainnet at block <Fact name="forkBlock" />, deploys Maat on a local Anvil node and runs the agent's round against it. It needs three things:

- `BASE_RPC_URL` set in your shell, pointing at a Base archive RPC. The test reads it from the environment, not from `.env`. When it is not set, the suite is skipped, not failed.
- The Base build of Anvil (`base-anvil`, installed with `base-foundryup`). On Windows, `MAAT_ANVIL_BIN` must point at the real `anvil.exe`.
- A free local port. The test refuses to start when something already answers on it.

`base-foundryup` comes from Base's [base/base-anvil](https://github.com/base/base-anvil) repository, not from this one. That repository's README installs it with this command, which downloads Base's installer from its `foundryup` folder and runs it:

```bash
curl -L https://raw.githubusercontent.com/base/base-anvil/HEAD/foundryup/install | bash
```

The same README says the Base build installs alongside a stock Foundry and does not overwrite it. Then run `base-foundryup` with the version that [agent/README.md](https://github.com/duongnq2798/maat/blob/main/agent/README.md#test) gives. That section also names the port the test uses.

The fork run uses a scripted proposer in place of Claude and a local sender in place of the CDP wallet, so it makes no Claude call and no CDP call. Setting `MAAT_GAS_LOG` to a file path makes the test write the gas limit and `gasUsed` of each transaction it sends. [Reproduce the fork run](/docs/guides/reproduce-the-fork-run) walks through it.

### typecheck

<ScriptEntry name="typecheck" />

Runs the TypeScript compiler without writing any files. It covers `src`, `test`, `scripts` and the Vitest configs, so it also checks the script files below without running them. It prints nothing more when the types are clean.

Trimmed output from the run at commit `95e4024`:

```text
> @maat/agent@0.1.0 typecheck
> tsc --noEmit
```

### gen:abi

<ScriptEntry name="gen:abi" />

Rewrites `agent/src/abi/generated.ts`, the ABIs the agent calls the chain with. It reads compiled ABIs from `contracts/out` and writes them into that one file. `contracts/out` is build output that Git does not track, so run `forge build` in `contracts/` first, and run this script again after any change to a contract's interface. It reads no setting and needs no network. The generated file is committed, so commit it when it changes. The script file is [gen-abis.ts](#gen-abists).

Trimmed output from the run on Windows at commit `95e4024`. The start of the absolute path in the last line is cut:

```text
> @maat/agent@0.1.0 gen:abi
> tsx scripts/gen-abis.ts

wrote …\agent\src\abi\generated.ts
```

## Script files

Only `gen-abis.ts` has an npm script, `gen:abi`. You run the other files in `agent/scripts` with Node or `npx tsx`.

### cdp-setup.ts

<ScriptFile name="cdp-setup.ts" />

<Callout type="warning" title="Owner only">

Only the vault owner runs this script, and only once. It talks to Coinbase. It creates the executor account in the CDP Server Wallet, or finds it if an account with that name exists, then creates an account policy and attaches the policy to the account. The policy accepts sending a transaction only on Base, only to the vault you pass in and only with a value of zero. It accepts signing a transaction only to that vault with a value of zero, and it rejects raw hash signing. Every run creates a new policy and points the account at it, so a second run creates a second policy.

It needs `CDP_API_KEY_ID`, `CDP_API_KEY_SECRET` and `CDP_WALLET_SECRET` in `.env`, and it reads `CDP_ACCOUNT_NAME` for the account name. Unlike the agent, it falls back to `maat-executor` only when that variable is absent. A blank `CDP_ACCOUNT_NAME=` gives it an empty name, which the CDP SDK rejects before any call to the CDP API, with `Either address or name must be provided`. The script stops with that error before it creates an account or a policy, so set a name or delete the line. It sends no transaction on Base and does not touch the vault.

```bash
cd agent
node --env-file=.env --import tsx scripts/cdp-setup.ts <VAULT_ADDRESS>
```

If the vault address is missing or is not an address, it prints its usage and exits with an error. On success it prints the account address and the policy id, then three steps that you do yourself: call `setExecutor` on the vault from the owner wallet, send a little ETH on Base to the account for gas, and set `MAAT_EXECUTOR` to the account address in `.env`. [deployments/README.md](https://github.com/duongnq2798/maat/blob/main/deployments/README.md) has the owner's command under "Switch the executor to the CDP Server Wallet". This page shows no output for the script, because the CDP path has never run against the real CDP.

</Callout>

### first-decision.ts

<ScriptFile name="first-decision.ts" />

For the owner, while their own wallet is the vault's executor. It builds one `BUY` intent the way the agent builds one, and prints the intent, the calldata of `previewIntent`, the calldata of `execute` with the [Builder Code](/docs/help/glossary#builder-code-erc-8021) suffix appended, and `cast` command templates with placeholders. It makes no network call, reads no `.env` file and no environment variable, holds no key and sends nothing. The owner runs the printed commands, signed with their own keystore. [deployments/go-live.md](https://github.com/duongnq2798/maat/blob/main/deployments/go-live.md) uses it for the owner's first two intents.

```bash
cd agent
node --import tsx scripts/first-decision.ts --vault <VAULT_ADDRESS> --token NVDAc --salt <SALT> --builder-code <BUILDER_CODE>
```

| Flag | Effect |
| --- | --- |
| `--vault` | Required. The vault address. A mixed-case address must have a valid checksum |
| `--token` | Required. `NVDAc`, `GOOGLc` or `AAPLc`, in any letter case |
| `--builder-code` | Required. Your Builder Code, which must match `^[a-z0-9_]{1,32}$` |
| `--salt` | Derives the intent id the agent's way, from the run id `first-decision:<salt>` and index 0. Give `--salt` or `--id`, not both |
| `--id` | Takes the intent id as given: `0x` and 64 hex digits, not all zeros |
| `--usd` | The dollars to spend, `5` by default, with at most 9 digits before the point and 6 after |
| `--action` | `BUY`, the default and the only action it builds. It refuses `SELL`, because a `SELL` amount is a raw stock amount and turning dollars into one takes the live price |
| `--rationale` | The rationale text. The intent carries its keccak256 hash, so keep the text. By default it names the amount and the token |

The intent's `minOut` is 0, as the agent sends it for a `BUY`: the vault swaps with the larger of `minOut` and its own oracle floor, so the script needs no price. Its payee is the zero address. The amount is not capped at the vault's USDC balance, which would take a read, so a `BUY` larger than the balance gets `INSUFFICIENT_BALANCE` from the vault. The vault accepts each id once, and `execute` reverts with [`IntentAlreadyUsed`](/docs/reference/errors#intentalreadyused) on an id it has seen, so every send needs a new salt. The send template sets a gas limit of <Fact name="executeGasFloor" />, the floor the agent uses for `execute`.

It exits with 0 when it prints the intent, or its usage for `--help`. It exits with 1 when a required flag is missing or a value is not valid, and with 2 when it cannot read the flags, for example an unknown one. Both print the error and the usage. It is not an npm script; `npm run typecheck` checks it and `npm test` runs its unit tests.

### gen-abis.ts

<ScriptFile name="gen-abis.ts" />

The file behind `npm run gen:abi`. Its list of targets is `MandateVault`, `ICreditAdapter`, `MarketCalendar`, `IB20Asset`, `IAggregatorV3` and `IERC20Minimal`. It writes one `export const` for each into `agent/src/abi/generated.ts`, under a header that says not to edit the file by hand. See [gen:abi](#genabi) for what it needs.

### smoke-claude.ts

<ScriptFile name="smoke-claude.ts" />

<Callout type="warning" title="Paid API call">

This script calls the paid Claude API. Each run is billed to the Anthropic account behind `ANTHROPIC_API_KEY`.

</Callout>

It asks Claude for one proposal and prints the result as JSON. It builds a fixed test vault from the fakes in `agent/test`, evaluates the policy on it and passes the result to the same `ClaudeProposer` the agent uses, with the model `claude-sonnet-5-5` written into the script. So it reads no chain, uses no RPC URL, no wallet and no CDP, and it ignores `MAAT_LOOP_MODEL`. It is not an npm script, and neither `npm test` nor `npm run typecheck` runs it.

The script does not load `.env` itself. The Anthropic SDK reads `ANTHROPIC_API_KEY` from the environment, so with the key set in your shell, run:

```bash
cd agent
npx tsx scripts/smoke-claude.ts
```

To have Node read the key from `agent/.env` instead, the way `cdp-setup.ts` reads its credentials, run the command below. It keeps the key out of your shell history.

```bash
cd agent
node --env-file=.env --import tsx scripts/smoke-claude.ts
```

This page shows no output for it, because the script calls the paid API.

## Messages the agent prints (from the code and unit tests; none seen in a live run)

Nothing is deployed, and the agent has run in live mode only on a fork, so none of the messages below has been seen outside the tests. Each one is quoted from `agent/src`, with what it means and the page that explains it. Text in angle brackets stands for a value the agent fills in. The last column names the unit test file that checks the message's text, with fakes in place of Claude, the CDP wallet and the chain, and None means that only the code holds it. For `invalid agent config`, the tests check the setting and the problem after the prefix.

### In the journal

A round writes these to its [journal](/docs/help/glossary#journal), `data/journal.jsonl`, as the `message` of an `error` or a `mismatch` line, or as the `error` of a `run` or a `skip` line. Each row says which. When a `run` line has an `error`, the round has no proposals from Claude, and a [compute bill](/docs/help/glossary#compute-bill) that is due, at least <Fact name="billMinUsd" />, is still queued as a `PAY_EXPENSE`. A `skip` line means that the proposal never became an [intent](/docs/help/glossary#intent), so nothing was previewed or sent for it.

| --- | --- | --- | --- |
| `state unavailable: <ERROR>` | An `error` line. A required read of the vault failed, and the round ended `no-state` without doing anything else. | [Run one round](/docs/guides/run-the-agent#run-one-round) | None |
| `vault executor is <ADDRESS>, agent is <ADDRESS>` | An `error` line. The vault's executor is not `MAAT_EXECUTOR`. The round ended `wrong-executor` right after it read the vault, before the policy or Claude, so it sent nothing. | [Common mistakes](/docs/guides/run-the-agent#common-mistakes), in Run the agent | None |
| `claude: <ERROR>` | A `run` line. The request to Claude failed before an answer came back. | `claude: malformed response: <ERROR>` | A `run` line. The answer had no usage or no content to read. The agent records a cost of zero for it. | [What happens if Claude is unavailable?](/docs/help/faq#what-happens-if-claude-is-unavailable) | None |

### After each round of the loop

Without `--once`, the loop prints one of these lines after each round. With `--once`, the agent prints the round's report instead, and an error ends the process.

| Message | What it means | Read | Unit test |
| --- | --- | --- | --- |
| `round <RUN_ID>: <STATUS>, sent <N>, skipped <M>` | The round returned its report. Any `<STATUS>` other than `done` needs a look. | [What to watch while it runs](/docs/guides/run-the-agent#what-to-watch-while-it-runs) | None |
| `round failed: <ERROR>` | The round threw an error instead of returning a report. The loop prints the error's stack and runs the next round after <Fact name="offSessionMinutes" />. | [Run it continuously](/docs/guides/run-the-agent#run-it-continuously) | None |
