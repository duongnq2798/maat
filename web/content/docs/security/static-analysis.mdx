This page records two static analyzers run over the Maat contracts, and what each high and medium finding means once it is read against the code. Static analysis is not an audit. The tools match code against known patterns: they report many findings that do not apply, and they miss bugs that fit no pattern. The contracts are unaudited ([What Maat does not claim](/docs/security/not-claimed#unaudited)), and the deployed contracts cannot be changed, so this page changes no code: it says what each finding is.

<Callout type="note" title="The result in one line">

By the reading below, none of the 2 high and 35 medium Slither findings in `contracts/src`, and none of the 2 high and 32 medium forge lint findings, is a bug in Maat's code. Each is a false positive or a choice the code makes on purpose, and the reason is given with its file and line. This is the project's own reading, not an independent review, and it does not show that the code has no bugs.

</Callout>

## Run it again

From the repository root, with the submodules checked out (`git submodule update --init`), and a virtual environment outside the repository:

```bash
python -m venv ../slither-venv
../slither-venv/bin/pip install slither-analyzer==0.11.6
cd contracts
../../slither-venv/bin/slither . --json ../../slither.json
forge lint src
forge lint src --severity info --severity gas --severity code-size
```

On Windows the two programs are in `..\slither-venv\Scripts`. Slither first runs `forge clean`, which deletes `contracts/out` and `contracts/cache`, then `forge build --build-info --deny never --skip ./test/** ./script/** --force`, and prints its report to stderr. Its JSON report was 4.6 MB and is not committed. `forge lint src` prints the high, medium and low lints, and the last command the other groups.

## Aderyn was not run

Aderyn, Cyfrin's static analyzer, is retired. Its repository, [Cyfrin/aderyn](https://github.com/Cyfrin/aderyn), is archived, and its README says that it has no supported installation or upgrade paths. On 2026-11-27 the npm registry answered 404 for the package `@cyfrin/aderyn`. The latest release, `aderyn-v0.6.8`, held checksum files, the source and an installer script that only prints that Aderyn has been retired and exits, with no binary for Windows or any other system. Building it from source needs a Rust toolchain, which was not installed for this run. So this page has no Aderyn results. forge lint, which ships with Foundry, is the second tool instead. Many of its lints carry the names of Slither detectors, so it is a second implementation of much the same checks, not a different method.

## Known compiler bugs

Not a static analyzer, but the same kind of check: the Solidity team's [bug list](https://github.com/ethereum/solidity/blob/develop/docs/bugs_by_version.json), read on 2026-11-27, gives ten known bugs for solc 0.8.28. Whether each can affect these contracts:

| Bug | Severity | Applies | Why |
| --- | --- | --- | --- |
| `TransientStorageClearingHelperCollision` | High | No | It needs `delete` on a transient variable, with `via_ir`. The only transient variable, `_activePool` in `AerodromeSwapAdapter`, is cleared by assigning `address(0)` (line 38), which the Solidity team's [announcement](https://blog.soliditylang.org/2026/02/18/transient-storage-clearing-helper-collision-bug/) says does not trigger the bug, and the adapter has no persistent storage |
| `OverlappingRecursiveStorageStructCopyCorruptionViaIR` | Medium | No | It needs a recursive struct. No struct in `contracts/src` has a struct member |
| `UnsoundSpillInMutualRecursion`, `SpillSlotCollisionAcrossMutualRecursion` | Medium, low to medium | No | They need mutual recursion. In Slither's call graph of the 25 contracts, no function calls itself, directly or through another |
| `YulOptimizerKnowledgeBaseStaleBookkeeping` | Low | Not ruled out | Any code compiled with `via_ir` and the optimizer may be affected. The Solidity team's [announcement](https://blog.soliditylang.org/2026/10/22/yul-optimizer-knowledge-base-stale-bookkeeping-bug/) says its conditions cannot be checked from the source, and that a rebuild of about 283,000 verified via-IR compilations gave no indication of affected contracts, which it says does not rule out that a contract is affected |
| `MisorderedNamedParametersInRequireWithCustomErrors` | Very low | No | It needs a `require` with a custom error. `contracts/src` has no `require`: it uses `if` and `revert`. The v4-core files compiled with it have plain `require`s with no error, in `FullMath` and `BitMath` |
| `LostStorageArrayWriteOnSlotOverflow` | Low | No | It needs a storage array that crosses the last storage slot. The three storage arrays, the vault's `_tokens` and `_payees` and the credit adapter's `_collaterals`, start at hashed slots that begin with `0x6e15`, `0x0175` and `0xb10e`, and hold a few addresses each |
| `OverlappingRecursiveStorageStructCopyCorruption`, `MemoryByteArrayElementDeleteClearsWholeWord`, `ABIDecodeStaticArrayMemoryAliasing` | Medium, low to medium, very low | No | Each needs the legacy pipeline, and the last also ABI coder v1. The contracts compile with `via_ir` and ABI coder v2 |

## What this does not show

- **No audit.** The verdicts are the project's own, written with Claude Code by the team that wrote the code. Nobody independent has checked them.
- **No proof.** A detector that finds nothing has only failed to match a pattern. Bugs in the logic, the economics or the trust between contracts fit no detector: a limit that is too loose passes every one.
- **One run.** This is one commit, run by hand on one machine. No analyzer runs in CI, so a later change to `contracts/src` is not covered until someone runs them again.
- **No other method.** No symbolic execution, no formal verification and no fuzzer beyond the Foundry suites ([How it is tested](/docs/security/testing)) was run, and Aderyn could not be.
- **Only the contracts.** The agent and the website were not analyzed, and the v4-core files were read only as far as Maat uses them.
