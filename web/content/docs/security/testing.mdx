This page maps each guarantee in the [security model](/docs/security/model) to the test that shows it, says what kind of test it is, and says what is not tested. You can run every test yourself, and most need no wallet, RPC URL or API key. Test counts are left out on purpose, because they go stale: [Run the tests](/docs/guides/run-the-tests) shows the commands, and the output tells you the counts today. Nothing is deployed, and no test here touches mainnet.

## Layers

| Layer | Where | Runs against | Needs |
| --- | --- | --- | --- |
| **Contracts, unit** | `contracts/test/*.t.sol` | Mocks of the tokens, feeds, pools and adapters, and committed calendar vectors | Nothing |
| **Contracts, invariant** | `contracts/test/invariant/*.sol` | Random sequences of calls against the same mocks | Nothing |
| **Contracts, fork** | `contracts/test/fork/*.t.sol` | Real Base state at two pinned mainnet blocks | A Base archive RPC |
| **Agent, unit** | `agent/test/*.test.ts` | Fakes for Claude, the CDP wallet and the chain | Nothing |
| **Agent, fork run** | `agent/test/integration/agent.fork.test.ts` | A local fork of Base, with a scripted proposer and a local sender | A Base archive RPC and `base-anvil` |
| **Parity, site and docs** | `web/test/*.test.ts` | The Solidity and TypeScript sources and the committed fork-run gas log | Nothing |
| **Site, end to end** | `web/e2e/*.spec.ts` | The built static site, in a browser | Playwright's Chromium |

Each layer has its own limit. Unit tests are fast and exact but use stand-ins. Fork tests use the real tokens and pools but cover few paths. No layer touches the real Claude API or the real CDP wallet.

## Contracts

The unit suites are `MandateVault`, `MandateVaultCredit`, `MandateVaultAdmin`, `MandateVaultMalformed`, `GuardLib`, `MarketCalendar`, `MarketCalendarVectors`, `PriceLib`, `AerodromeSwapAdapter` and `AaveV4CreditAdapter`. They run against mocks in `contracts/test/mocks`: a mock [B20](/docs/help/glossary#b20) token with switches that make each read revert, a mock feed, a mock pool, and mock swap and credit adapters. The mocks are what make the tests exact: a test can make `isPaused` revert, move the clock to a Saturday, or have the swap return a hair less than the floor. The price is that a mock shows the vault's logic and not the behavior of the real contract it stands for. Here is one such test:

```solidity title="contracts/test/MandateVault.t.sol#L114-L121"
    function test_slippageFloorIsEnforcedEvenIfAgentSendsZero() public {
        adapter.setNextOut(0.098e8); // floor is 0.099e8 (1% below oracle-implied 0.1e8)
        (bool allowed, Reason r) = _exec(_intent(Action.BUY, 20e6));
        assertFalse(allowed);
        _assertReason(r, Reason.SWAP_FAILED);
        assertEq(usdc.balanceOf(address(vault)), 200e6);
        assertEq(usdc.allowance(address(vault), address(adapter)), 0);
    }
```

The [intent](/docs/help/glossary#intent) asks for a `minOut` of zero. The mock adapter returns slightly less than the floor the vault computed from the oracle. The swap fails, the vault records `SWAP_FAILED`, the USDC stays and the allowance is reset.

## Invariant tests

The unit tests check one example each. The invariant suite, [`MandateVaultInvariants.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/invariant/MandateVaultInvariants.t.sol), lets Foundry call a set of handler functions in a random order with random inputs, many calls per run and many runs, and checks the invariants below after every call. It runs on the same mocks as the unit tests: a vault with two listed stocks, an unlisted one, two allowlisted payees and the mock credit adapter, and three valid mandates for the owner to switch between.

### Handlers

No handler reverts itself, so every outcome is counted instead. The trade, expense and credit handlers send intents the way the agent does: before each `execute` they call `previewIntent` as the executor, with `tx.origin` set to the executor too. One send in 16 comes from a stranger and one in 16 reuses the last intent id, to reach the two reverts.

| Handler | What it does |
| --- | --- |
| **Trade** | `BUY` and `SELL` of the two listed stocks, and now and then of the unlisted one. Most sizes are well under the per-trade cap, some are near it or over it, and some are zero. The mock swap pays between the slippage floor and the oracle-implied amount, except one time in 32 when it pays under the floor and one time in 32 when the intent's `minOut` is above what it pays |
| **Expense** | `PAY_EXPENSE` to one of the two allowlisted payees, or to an address off the allowlist one time in four |
| **Credit** | `SUPPLY`, `BORROW`, `REPAY` and `WITHDRAW_COLLATERAL` on the mock credit adapter, with health factors scripted per call: mostly above the target, sometimes between the floor and the target, sometimes below the floor, and now and then a check after the action that disagrees with the projection |
| **Time** | Moves the clock into a regular session, by a few minutes, across UTC midnight or by days, so a run can cross nights, weekends, holidays and early closes. It refreshes the feeds as it goes, except that now and then a feed keeps its old answer and goes stale, or moves past the [premium](/docs/help/glossary#premium) limit |
| **Owner** | Queues, cancels and applies changes between the three mandates at whatever time the run is at, and keeps its own record of when each was queued |

### Invariants

| Invariant | What fails it |
| --- | --- |
| `invariant_executeRevertsOnlyWithNotExecutorOrIntentAlreadyUsed` | `execute` reverts with anything but `NotExecutor` for the stranger or `IntentAlreadyUsed` for the reused id, one of those two does not revert, or `previewIntent` reverts |
| `invariant_spentOnDayStaysWithinTheDailyCap` | `spentOnDay` for a UTC day the run touched, midnight crossings included, is over the largest daily cap in force that day, or differs from the sum of the trades and payments `execute` allowed that day |
| `invariant_noAllowanceOutlivesACall` | The vault leaves an allowance of USDC or either stock to the swap adapter or the credit adapter after any call |
| `invariant_usdcLeavesOnlyToAnAdapterOrAPayee` | A USDC transfer out of the vault goes to anyone but the swap adapter, the credit adapter or an allowlisted payee, or the USDC held by the vault, the two adapters and the payees stops adding up to what was minted |
| `invariant_previewMatchesExecuteUntilItActs` | `previewIntent`, called right before `execute`, gives another reason than `execute`. A preview of `OK` followed by `SWAP_FAILED`, `TRANSFER_FAILED`, `CREDIT_FAILED`, or the adapter's own health check after a `BORROW` or a `WITHDRAW_COLLATERAL`, is not a mismatch: the preview cannot see those |
| `invariant_mandateChangesOnlyThroughATimelockedApply` | `mandateHash` differs from the last mandate applied with `applyMandate`, or an apply succeeds before the timelock (<Fact name="timelockHours" />) or after the grace period (<Fact name="gracePeriodDays" />) that follow the queueing of that exact mandate, or fails inside that window, or fails with another error than the one the handler's record predicts. The handler reads `TIMELOCK` and `GRACE_PERIOD` from the vault |

`afterInvariant` then checks that the run reached what the invariants are about, so that it cannot pass by doing nothing. Each run must have allowed several trades, payments and credit actions, applied and refused at least one mandate change, reached both expected reverts, spent on both sides of a UTC midnight, landed in an open session several times, and refused intents with `MARKET_CLOSED`, `PAYEE_NOT_ALLOWED`, `INSUFFICIENT_BALANCE` and at least six kinds of refusal in all.

### Run them

The invariant suite runs as part of `forge test --no-match-path "test/fork/*"`. The `[invariant]` table in [`foundry.toml`](https://github.com/duongnq2798/maat/blob/main/contracts/foundry.toml) keeps the default campaign short, well under a minute, and `fail_on_revert` makes a reverting handler fail the run, since the handlers are built not to revert. For the suite alone, or for a longer search with the `deep` profile:

```bash
cd contracts
forge test --match-path "test/invariant/*"
FOUNDRY_PROFILE=deep forge test --match-path "test/invariant/*"
```

Each run starts from a new random seed. When a run fails, Foundry prints the shortened sequence of calls that broke the invariant.

### What the invariants do not cover

- **Real contracts.** The swap adapter pays a scripted amount, the pools' TWAP does not move, and the credit adapter's health factors are scripted. Pool price impact, Aave interest and liquidation are not modelled.
- **Dependencies that break their ABI.** Every mock follows its ABI, so the first invariant says nothing about a dependency that does not. [`MandateVaultMalformed.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/MandateVaultMalformed.t.sol) shows what happens otherwise: `execute` reverts.
- **Other owner actions.** Only mandate changes are fuzzed. Token and payee changes, `setPaused`, `setExecutor`, `withdraw` and `fund` are not called during a run, so the stock list and the payee allowlist stay fixed.
- **Other state the vault reads.** The B20 pause flag, the transfer policy and the multiplier never change during a run, so `TOKEN_PAUSED`, `POLICY_BLOCKED` and `MULTIPLIER_COOLDOWN` are not reached. The handlers do not aim at `CONCENTRATION`, `TRANSFER_FAILED` or `CREDIT_FAILED` either, and the coverage check does not require them.
- **The calendar itself.** The time handler can land on a holiday or after an early close, but the coverage check does not require it to. The calendar vectors below cover those dates.
- **Proof.** A campaign is a random search of bounded length. A sequence it did not try can still break a property.

## Calendar vectors

[`MarketCalendarVectors.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/MarketCalendarVectors.t.sol) checks `MarketCalendar` against two JSON files in `contracts/test/vectors`, read with `vm.readFile` and `vm.parseJson`. A Node script, [`gen-vectors.mjs`](https://github.com/duongnq2798/maat/blob/main/contracts/test/vectors/gen-vectors.mjs), writes them with `Intl.DateTimeFormat` and the `America/New_York` time zone, so the expected values come from the IANA time zone data in Node and share no date logic with the contract.

| File | What it holds | What the test checks |
| --- | --- | --- |
| `us-eastern-dst.json` | The instant of each DST start and end from 2007, when the current US rule began, to 2100, found to the second | `etOffsetSeconds` one second before and at each change |
| `nyse-calendar.json` | The NYSE holidays and 13:00 ET early closes of 2026 and 2027 that the calendar's constructor preloads, and fixed ET times on each of those dates | `isHoliday` and `earlyCloseMin` on each date, that no other day of 2026 or 2027 is preloaded, and `localTime` and `isOpen` in both session modes at each fixed time |

The holiday list in the script is typed from the dates the contract encodes, so these vectors catch a change to the contract or to its date arithmetic, not a mistake in the list itself. Future years assume the US keeps its current DST rule, which is also what the contract assumes. To regenerate the files, run this from the repository root with Node 24 and check that `git diff` shows no change:

```bash
node contracts/test/vectors/gen-vectors.mjs
cd contracts && forge test --match-path test/MarketCalendarVectors.t.sol
```

## Fork tests against real Base state

The contract fork tests run the real B20 tokens, Chainlink feeds, Aerodrome pools and [Aave V4](/docs/help/glossary#aave-v4) at two pinned mainnet blocks: `BLOCK_SESSION` (<Fact name="forkBlock" />, a Thursday, <Fact name="forkDay" />, in session) and `BLOCK_WEEKEND` (a Saturday, 2026-10-31). Foundry forks the chain locally, so nothing is broadcast. They need a Base archive RPC. This is the README's table:

| Test file | What it shows |
| --- | --- |
| [`MandateVaultFork.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/fork/MandateVaultFork.t.sol) | Buys and sells NVDAc in session, buys the basket, refuses a real-weekend buy in both session modes, and bounds a compromised executor |
| [`MandateVaultCreditFork.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/fork/MandateVaultCreditFork.t.sol) | The credit loop in session; then, with the clock moved to Saturday, borrowing is refused while repay and withdraw still work |
| [`AaveV4CreditAdapterFork.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/fork/AaveV4CreditAdapterFork.t.sol) | Full supply, borrow, repay and withdraw on the Aave V4 MAG7 Spoke; reserve ids match the chain; a borrow below the minimum [health factor](/docs/help/glossary#health-factor) reverts |
| [`AerodromeSwapAdapterFork.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/fork/AerodromeSwapAdapterFork.t.sol) | Buys and sells NVDAc directly against the Slipstream pool |
| [`PriceLibFork.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/fork/PriceLibFork.t.sol) | The live basket trades near the oracle price |

| [`DeployFork.t.sol`](https://github.com/duongnq2798/maat/blob/main/contracts/test/fork/DeployFork.t.sol) | The deploy script wires every contract and address correctly |

What a [fork test](/docs/help/glossary#fork-test) does not show:

- **It is a block, not a deployment.** It shows what the code does against real state at that block. It says nothing about how the system behaves on mainnet over time.
- **The vault is funded by a test cheat code** in the two vault fork tests, not by an owner's `fund` call.
- **Several paths have no fork test.** No fork test pauses the vault, rotates the executor, queues a rule change or withdraws a stock. The compromised-executor test deploys the vault without a credit adapter, so it does not try a borrow.
- **The Saturday round of the agent's fork run is the same fork with the clock moved ahead.** The contract fork tests have a real Saturday block, and the agent's run does not.

## The agent

The agent's unit tests use fakes. The fake chain, receipts and sender are in [`agent/test/fakes`](https://github.com/duongnq2798/maat/tree/main/agent/test/fakes) (`fakeChain.ts`, `fakeReceipts.ts` and `fakeSender.ts`). This is the mismatch test, the one that makes the agent stop when its preview and the vault disagree:

```typescript title="agent/test/runOnce.test.ts#L357-L367"
    it("halts when the preview said OK but the vault refused", async () => {
      const t = await setup({ batch: TWO });
      t.receipts.verdict = () => ({ allowed: false, reason: 15 });
      const r = await runOnce(t.deps);
      expect(r).toMatchObject({ status: "halted", haltReason: "mismatch: preview OK, vault SWAP_FAILED" });
      expect(t.inner.sent).toHaveLength(1);
      const rows = await t.journal.read();
      expect(rows.find((e) => e.kind === "mismatch")).toMatchObject({ preview: "OK", decision: { allowed: false, reason: "SWAP_FAILED" }, message: "mismatch: preview OK, vault SWAP_FAILED" });
      expect(rows.find((e) => e.kind === "intent")).toMatchObject({ gate: "execute", decision: { allowed: false, reason: "SWAP_FAILED" } });
      expect(t.store.pending()).toEqual([]);
    });
```

The agent's fork run, [`agent.fork.test.ts`](https://github.com/duongnq2798/maat/blob/main/agent/test/integration/agent.fork.test.ts), goes one step further. It deploys the contracts on a local fork from the compiled artifacts, through its own helper [`deploy.ts`](https://github.com/duongnq2798/maat/blob/main/agent/test/integration/deploy.ts), wired the way the deploy script wires them. It funds the vault with `fund`, and runs rounds with a scripted proposer in place of Claude. It sends through the guarded sender, with a local sender in place of the CDP wallet. It checks that every transaction carries the Builder Code and an explicit gas limit, and that each preview matches the onchain `Decision`. Its gas figures are committed to `fork-gas.json`. [Reproduce the fork run](/docs/guides/reproduce-the-fork-run) runs it.

<Callout type="warning" title="Not exercised">

Claude and the CDP wallet are fakes in every agent test. The Claude proposer is tested against a fake client, and no output from the real Claude API is committed. ## Parity tests: the site and these docs

The website and these docs carry numbers, signatures and code that come from the contracts and the agent. The parity tests read those sources and fail when a page drifts from them. They run offline, in `web/`.

| Gate | What fails it | File |
| --- | --- | --- |
| **Facts** | A number on the landing page that differs from the Solidity sources, the agent's policy or the committed fork-run gas log | [`facts.test.ts`](https://github.com/duongnq2798/maat/blob/main/web/test/facts.test.ts) |
| **Docs facts** | A number only the docs cite (the grace period, the gas cap, the agent's defaults) that differs from the file it names | [`docs-facts.test.ts`](https://github.com/duongnq2798/maat/blob/main/web/test/docs-facts.test.ts) |
| **Generated data** | The committed reference data (functions, events, errors, types, addresses and the agent's settings) differs from what the sources now parse to. The test says to run `npm run docs:gen` | [`docs-gen.test.ts`](https://github.com/duongnq2798/maat/blob/main/web/test/docs-gen.test.ts) |
| **Coverage** | A public function, event, error, enum, struct, agent setting or script with no reference entry | [`docs-coverage.test.ts`](https://github.com/duongnq2798/maat/blob/main/web/test/docs-coverage.test.ts) |
| **Content** | A page whose frontmatter, links, anchors, repository paths or typed numbers are wrong, or whose code excerpt differs from the lines of the file it names | [`docs-content.test.ts`](https://github.com/duongnq2798/maat/blob/main/web/test/docs-content.test.ts) |
| **Structure** | A written page that is not in the information architecture, or a section list out of order | [`docs-ia.test.ts`](https://github.com/duongnq2798/maat/blob/main/web/test/docs-ia.test.ts) |

The built site is checked too. `npm run check:out` fails if the export contains a third-party script, is missing a page or lacks the Markdown copy of a docs page. The Playwright end-to-end tests load pages at several widths and fail on page overflow or a console error.

These gates prove that numbers, signatures, excerpts, links and the shape of the reference match the code. They do not prove that a sentence is true. The prose on these pages was checked by reading it against the code and the tests, and a reader can do the same with the links above.

## What is not tested

| Not tested | Why it matters |
| --- | --- |
| **No audit** | Nobody independent has reviewed the code. See [What Maat does not claim](/docs/security/not-claimed) |
| **Fuzzing beyond the mocks** | The invariant suite runs on mocks only, no fuzz test runs on a fork, and [What the invariants do not cover](#what-the-invariants-do-not-cover) lists what the suite leaves out |
| **The real Claude API** | The proposer runs against a fake client, and no output from the real API is committed |
| **The real CDP wallet and its policy** | The CDP code runs against a fake client, and no test shows that CDP enforces the policy |
| **Mainnet** | No Maat contract is deployed, so every test is a unit test or a fork |
| **A real split or dividend** | The assumption that the feed includes the multiplier has not been observed across one |
| **Some failure paths** | No unit test makes the feed's `latestRoundData` or the pool's `observe` revert during `execute`, none makes a plain `decimals` read or a stock's `balanceOf` revert, and none calls `withdraw` with a token that has no code. A USDC `balanceOf` that reverts is tested, and `execute` reverts with it |
| **A hostile owner** | The vault has no defense against one, so there is nothing to test |
| **Continuous integration** | There is no CI in this repository yet. The suites run when someone runs them, so any claim here is as fresh as the last run |

If you can think of a test that belongs on this list, or one that fails, [Report a vulnerability](/docs/security/report-a-vulnerability) says how to tell the team.
